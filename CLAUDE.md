# RADAR — backlog y decisiones del proyecto

Notas persistentes para retomar el trabajo entre sesiones. RADAR es un SaaS
contable/tributario chileno (React + Vite + Supabase, todo en `src/App.jsx`).

## Principio de arquitectura (no renegociable)

Ninguna clave/credencial real del usuario (Clave Tributaria del SII, llaves
de API de terceros como Fintoc) toca un servidor de RADAR ni de Supabase.
Todo pasa por un puente local (`tools/*-local-server.mjs`) que el propio
usuario corre en su máquina — ver `tools/README.md`. Cualquier diseño nuevo
que implique guardar una clave "cifrada en el servidor" (como hace Nubox con
su Integración SII) se descarta por defecto a menos que el usuario decida
explícitamente lo contrario.

Decisiones confirmadas con el usuario antes de implementar:
  - **Tasa PPM**: campo nuevo `eObj.tasaPPM` (default 1%), editable en Empresa > Tributario, mismo patrón que `tasaMutual` — el SII la fija por empresa según su historial, no es un número nacional único.
  - **Tasa IDPC / Impuesto a la Renta**: campo nuevo `eObj.tasaIdpc` (default **12,5%**, no 25%). Antes de hardcodear busqué la tasa vigente y los resultados eran contradictorios (tasa histórica 25% vs. rebaja transitoria Ley 21.755 a 12,5% para años comerciales 2025-2027, con un proyecto de reconstrucción nacional en trámite que podría volver a cambiarla) — el usuario confirmó explícitamente usar 12,5%. El Impuesto a la Renta estimado **solo se calcula para régimen "Pro Pyme General (14 D N°3)"** (confirmado con el usuario, es el régimen por el que se empezó); para cualquier otro régimen la tarjeta muestra "No disponible para régimen X" en vez de inventar una fórmula no verificada (Transparente no paga IDPC a nivel empresa, por ejemplo).
